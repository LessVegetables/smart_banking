# Контракты между треками

Контракты — это форматы данных, на которых встречаются три трека. Пока они не меняются, треки работают параллельно и не ждут друг друга.

**Статус:** ещё не определены — это задача T00 в [TASKS.md](TASKS.md).

## Где лежат

- `apps/api/contracts.py` — Pydantic-модели. Это единственный источник правды; описание ниже только перечисляет, что там должно быть.
- `tests/fixtures/` — пример JSON для каждой модели. Трек 2 строит движок на этих примерах, трек 3 — экраны, ещё до того, как готов синтетический мир.

## Что входит

| Контракт | Кто производит → кто потребляет | Содержание |
|---|---|---|
| Ответы источников | мок-сервис (трек 1) → адаптеры (трек 1) | По модели на каждый источник: ЕГРЮЛ/ЕГРИП, ФНС (+ГИР БО), БКИ, ФССП, арбитраж/Федресурс, 115-ФЗ, счета банка. Урезанные поля, нужные конвейеру (SPEC §5) |
| `Fact` | адаптеры (трек 1) → движок (трек 2) | Название факта, заявленное значение, подтверждённое значение, источник, уровень надёжности, время получения |
| `DataQuality` | признаки (трек 1) → движок (трек 2), досье (трек 3) | Четыре показателя качества данных по счёту и итоговый уровень `FULL` / `PARTIAL` / `THIN` (SPEC §5.1) |
| `Features` | признаки (трек 1) → скоринг (трек 2) | Список признаков скоринговой карты с типами; отсутствующее значение — отдельный интервал «нет данных» |
| Файл скоринговой карты | обучение (трек 1) → скоринг (трек 2) | `scorecard_vN.json`: версия, интервалы и баллы по каждому признаку, масштабирование баллов, границы грейдов |
| `Decision` | движок (трек 2) → интерфейсы (трек 3) | Статус, маршрут, коды причин, PD и грейд, вклады факторов, расчёт лимита и ставки по составляющим, предложения, контрфактические подсказки, версии модели и политики |

## Как менять контракт

1. Отдельный PR, который меняет `contracts.py` **и** соответствующие примеры в `tests/fixtures/`.
2. Тесты проходят.
3. PR одобряют все три программиста.
4. Если изменение ломает совместимость, в журнал решений в `TASKS.md` добавляется строка.
