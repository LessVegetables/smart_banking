# Клиентский интерфейс v2

## Подача заявки

Клиент вводит ИНН, подтверждает данные синтетической карточки и три согласия, затем указывает цель, сумму, срок и желаемое время получения денег. Для инвестиционного кредита дополнительно нужны описание оборудования, его цена, собственный взнос и ИНН поставщика. Рекомендованный продукт соответствует карте целей из `apps/api/offers.py`.

Прогресс этих шагов хранится в `sessionStorage` текущей вкладки. Перезагрузка страницы восстанавливает адрес текущего шага, карточку компании, выбор согласий и введённые параметры потребности. Данные доступны только в этой вкладке и удаляются браузером после её закрытия; успешная отправка и начало новой заявки очищают черновик. Запрос создаётся через `POST /api/v2/applications` с ключом идемпотентности, карточкой компании и согласиями.

После отправки клиент попадает на экран анализа заявки. Он опрашивает `GET /api/v2/applications/{id}` и показывает текущий этап, состояние каждого источника и итог решения. Тексты ошибок источников клиенту не передаются. Когда конвейер завершён, экран показывает доступные клиенту причины, уровень данных, запрошенные документы или краткую сводку предложений и предлагает продолжить в кабинете. Экран общий для веб-кабинета и mini app.

После выбора предложения клиент может прочитать сформированные документы, запросить демонстрационный код и подписать весь комплект одним кодом. Код показывается на экране вместо SMS (`# MOCK:` — код не отправляется во внешнюю систему). После подписи экран следит за отлагательными условиями, а при выдаче показывает текст результата из API. На главной странице показывается предодобренный овердрафт выбранной в этой вкладке компании, если API вернул действующее предложение; переход заполняет цель, сумму и срок заявки. API пока не связывает профиль пользователя с компанией (см. `docs/v2/NOTES.md`, T25), поэтому UI использует выбранную карточку и требует сохранённые согласия, но серверную проверку владения это не заменяет.

Сборка клиента из корня репозитория: `npm.cmd run build`.

## Демо-профиль и история

Вход под одним и тем же именем открывает устойчивый демо-профиль, поэтому заявки сохраняются после выхода и повторного входа. В форме компании демо-пользователь выбирает любую текущую компанию из каталога T12; каталог строится по доступным компаниям синтетического мира и всегда содержит запасной вариант. Для входа с реальным Telegram-аккаунтом каталог демо-компаний не применяется. Раздел «Мои заявки и финансирование» объединяет старые заявки и заявки v2, включая выданное финансирование.

## Рабочее место сотрудника

Кнопка «Для сотрудников» открывает вход по `STAFF_PASSWORD`; при входе сотрудник выбирает роль андеррайтера или риск-менеджера. Очередь показывает заявки `in_review` из конвейера v2. В досье доступны статусы и ошибки источников, выписки клиента, качество данных, факты «заявлено / подтверждено», маршрут и причины, флаги, вклад признаков в скоринг с базовыми баллами, теневая модель, расшифровки лимита и ставки, а также аудит, подписание и выдача. Экран читает staff API v2; действия по заявке выполняются отдельным интерфейсом.
