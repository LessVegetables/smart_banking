# Стоп-факторы и флаги (T14)

`stop_factors.py` вычисляет правила SPEC §7 после обогащения источниками. Модуль принимает снимок ответов и дату оценки; признаки просрочек и выручки считает той же библиотекой, что использует скоринговая карта.

Стоп-фактор означает автоматический отказ без скоринга. Совпадение по ПОД/ФТ возвращает сотруднику подробную причину, а клиенту — только нейтральное сообщение. Флаг требует ручного рассмотрения. Ошибка ФНС, ФССП или арбитража сама по себе не останавливает обработку и создаёт отдельный флаг.

Списки запрещённых и требующих ручного рассмотрения ОКВЭД читаются из `config/stop_factors.json`; списки перенесены из старой конфигурации без изменения значений. Числовые границы берутся из SPEC §7. Флаг расхождения выручки сравнивает заявленную величину с `estimate_12m`, а не с выручкой, как она подана в ФНС.

**Ограничение политики:** SPEC не задаёт таблицу соответствия между целью заявки и ОКВЭД, поэтому такой флаг пока не вычисляется. Значения штрафов за недоступные необязательные источники также не заданы; T14 передаёт флаги, а T15 должен применять согласованную политику штрафов.
