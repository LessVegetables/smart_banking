# Миграции базы данных

Схема базы данных версионируется Alembic. При запуске API и отдельного worker функция `init_db()` применяет миграции до текущей версии. Новая БД получает схему из базовой ревизии; существующая legacy-БД принимается за эту ревизию без пересоздания таблиц и потери данных.

Базы, созданные до внедрения Alembic, автоматически принимаются за базовую ревизию `0001_baseline`, если присутствует полный набор таблиц legacy-схемы; при частичной схеме запуск завершится явной ошибкой. После отметки применяются последующие миграции. Новые таблицы схемы добавляются только миграциями, а не `Base.metadata.create_all`, чтобы история изменений оставалась управляемой.

Ревизии находятся в `apps/api/migrations/versions/`. Новую ревизию можно создать командой `alembic revision -m "описание изменения"`, предварительно задав `DATABASE_URL` для целевой БД. Применение выполняется командой `alembic upgrade head`; для существующей БД до Alembic сначала один раз запустите приложение, чтобы оно отметило базовую ревизию и применило новые изменения. В Docker Compose API запускается до worker, поэтому миграция завершается до старта worker. В окружении с несколькими репликами миграцию следует применять один раз отдельным шагом развёртывания до масштабирования приложения.
