# Альфа · Бизнес

Рабочий локальный MVP по `ARCHITECTURE.md`: веб-кабинет, Telegram Mini App, единый FastAPI backend, адаптивная анкета, детерминированный кредитный движок, документы и рабочее место андеррайтера.

## Открыть готовую версию

В этой рабочей папке зависимости установлены, production-сборка подготовлена.

```powershell
cd .
.\start.ps1
```

- Веб-кабинет: http://127.0.0.1:8000/
- Mini app: http://127.0.0.1:8000/mini/
- Рабочее место: http://127.0.0.1:8000/staff
- OpenAPI: http://127.0.0.1:8000/docs

Оба интерфейса обслуживаются одним сервером. В одном браузере у них общая сессия и данные. Кнопки «Подобрать финансирование» и сценариев создают демо-кабинет при первом использовании. Демо-вход создаёт отдельного пользователя, а не открывает общий аккаунт всем посетителям.

Если 8000 занят, `run.py` выбирает свободный порт в диапазоне 8000–8020 и печатает точные ссылки. Для фиксированного порта задайте `PORT`. В режиме разработки адрес API для Vite по умолчанию — порт 8000; при его изменении обновите `server.proxy` в `vite.config.ts`.

## Установка с нуля

Нужны Python 3.12+, Node.js 22+ и npm.

```powershell
.\setup.ps1
.\start.ps1
```

Если политика PowerShell запрещает локальные скрипты, можно выполнить команды напрямую:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
npm.cmd ci --cache .npm-cache
npm.cmd run build
.\.venv\Scripts\python.exe run.py
```

Параметры задаются переменными окружения или через `.env` на основе `.env.example`. Настоящие ключи в репозиторий не добавляются. Файл `.env` читает `run.py`; при запуске непосредственно через uvicorn экспортируйте переменные самостоятельно.

Для разработки frontend: `npm.cmd run dev`; параллельно запускается `.venv\Scripts\python.exe run.py`. Vite проксирует `/api` на порт 8000. После изменения клиента обновите production-сборку командой `npm.cmd run build`.

## Что работает

- Общая схема из 43 вопросов: цель, реквизиты бизнеса, финансы, обязательства и детали продукта. Показываются только активные ветки. Срок бизнеса вычисляется из даты регистрации.
- Один вопрос на экране, крупные варианты, прогресс по разделам, возврат и серверное сохранение каждого ответа после «Продолжить».
- Ветки сезонности, действующих кредитов, просрочек, оборудования и кредитной линии. Изменение родительского ответа исключает скрытые ответы из расчёта.
- Сводка перед подачей; предварительный расчёт отделён от подтверждённой заявки.
- Три продукта с разными сроками, ставками и ограничениями. Для линии — отдельная модель полной выборки и ожидаемого использования.
- Стоп-факторы, объяснимый скоринг, расчёт платёжной нагрузки, ограничения по выручке и залогу, контрпредложения и совместимые альтернативы.
- Серверная очередь заданий с повторными попытками и восстановлением истёкшей аренды задания. Локально worker встроен в сервер; отдельный запуск: `python -m apps.api.worker` при `WORKER_ENABLED=false` у API.
- История заявки, версии решений и неизменяемые снимки входных данных и политики.
- Принятие/отклонение предложения, демонстрационное подписание и выдача.
- Закрытая загрузка PDF/PNG/JPEG до 10 МБ. Загрузка не меняет риск: содержание подтверждает сотрудник.
- Очередь андеррайтера, подтверждение выручки и динамики, пересчёт, ручное предложение, отказ с обязательным комментарием.
- Защищённые cookie-сессии, разделение доступа пользователей и сотрудников, проверка Origin, серверная проверка Telegram `initData`, контроль версий и идемпотентная подача.
- Помощник с рабочим справочным режимом без ключей и необязательным подключением языковой модели.

## Проверить семь сценариев

На главной странице внизу находятся карточки готовых синтетических бизнесов. Выбор заполняет новую анкету; на экране сводки нажмите «Рассчитать предложения», подтвердите подачу и нажмите «Подать заявку».

| Сценарий | Результат |
|---|---|
| Здоровый бизнес | Одобрение → принятие → демо-подписание → демо-выдача |
| Рост с нагрузкой | Контрпредложение с уменьшением суммы |
| Новое оборудование | Предложение с залогом и ограничением суммы |
| Уточнение финансов | Запрос документов; после подтверждения выручки 36 млн ₽ и стабильной динамики — одобрение |
| Сложный профиль | Запрос документов; при сохранении показателей — ручное рассмотрение |
| Подходящий формат | Альтернатива: оборотный кредит вместо линии |
| Стоп-фактор | Отказ до скоринга с объяснением |

Скрипты `setup.ps1` и `start.ps1` при первом запуске создают локальный `.env` со случайным паролем сотрудника (`STAFF_PASSWORD`) и паролем локальной БД для Compose. Существующий `.env` не перезаписывается. Для входа сотрудника скопируйте значение из своего `.env`. При ручной настройке задайте пароль длиной от 12 символов и перезапустите сервер. Общего фиксированного пароля нет.

Чтобы проверить документы, загрузите настоящий тестовый PDF или изображение на странице заявки, затем откройте `/staff` в отдельном профиле браузера или приватном окне: вход сотрудника меняет текущую cookie-сессию. Сотрудник видит очередь и загруженные документы. «Подтвердить документы и пересчитать» сохраняет новые проверенные значения. «Рассчитать ручное предложение» не обходит стоп-факторы, высокий риск без подтверждения документов и количественные ограничения.

## Telegram

В браузере `/mini/` работает как компактное приложение. Внутри Telegram подключается официальный Web App SDK; сервер проверяет HMAC и возраст данных авторизации (до 5 минут). Для запуска из бота нужны `TELEGRAM_BOT_TOKEN`, доступный HTTPS-адрес, корректный `APP_ORIGIN`, `COOKIE_SECURE=true` и настройка меню бота на `<адрес>/mini/`.

В настройках есть привязка кабинетов: пользователь создаёт одноразовый код в веб-сессии и подтверждает его из авторизованной Telegram-сессии. Совпадение имени или телефона не объединяет аккаунты. В MVP коды живут в памяти API две минуты, поэтому привязка предполагает один процесс API; для нескольких реплик их следует перенести в общую БД.

## Языковая модель

По умолчанию помощник объясняет вопросы и решения по серверным шаблонам и явно сообщает о справочном режиме. Чтобы включить модель, задайте:

```dotenv
ASSISTANT_LLM_ENABLED=true
OPENAI_API_KEY=<ключ>
OPENAI_MODEL=<доступная в вашем аккаунте модель>
```

Адаптер использует Responses API, без инструментов и возможности менять заявки; `store=false`, тайм-аут 12 секунд. К модели передаются вопрос пользователя и минимальный справочный контекст, без файлов, реквизитов и полного финансового профиля. Типичные цифровые идентификаторы и email в сообщении маскируются. Неизвестные контексту числа в ответе отклоняются. Ошибка провайдера возвращает рабочий шаблонный ответ.

Интеграция подготовлена по [официальной документации OpenAI](https://developers.openai.com/api/docs/guides/text). Живой вызов без предоставленного ключа не выполнялся; проверяются контракт и fallback. Модель помогает с объяснениями, а все авторитетные условия остаются в карточках, рассчитанных движком.

## Данные и инфраструктура

По умолчанию SQLite находится в `data/alfa.db`, документы — в `data/documents/`. Эти данные сохраняются между перезапусками и исключены из Git. Для PostgreSQL задайте `DATABASE_URL=postgresql+psycopg://...`. Доступ к данным идёт через SQLAlchemy.

Для закрытого S3-совместимого хранилища задайте `S3_BUCKET`, при необходимости `S3_ENDPOINT_URL`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_DEFAULT_REGION`. Бакет предварительно создаётся закрытым. Скачивание идёт через API с проверкой доступа, публичных URL нет. Без S3 используется локальный адаптер.

Docker Compose поднимает PostgreSQL, API и отдельный worker:

```dotenv
POSTGRES_PASSWORD=<пароль из букв и цифр для локального compose>
STAFF_PASSWORD=<свой пароль длиной от 12 символов>
```

```powershell
docker compose up --build
```

Docker, PostgreSQL, S3 и вход внутри реального Telegram подготовлены в конфигурации, но без соответствующих сервисов и токена в этой сессии не проверялись. Проверенный локальный путь — SQLite и закрытые файлы на диске. Compose использует локальную привязку порта и не публикует сервис наружу.


## Границы готовности

Это хакатонный прототип. Реестры, ФНС и БКИ — детерминированные моки, а не реальные запросы. Подписание и выдача имитируются. Нет реальной оценки залога, OCR, ЭП и денежных переводов. Финансовые документы подтверждает сотрудник вручную. Синтетические веса и ставки собраны в `config/rules.json`; правила не описывают кредитную политику банка. Полный промышленный банковский контур, миграции существующих БД, мониторинг доставки уведомлений и антивирусная проверка файлов требуют отдельного этапа.
